# 使用 DeepSeek

项目已预设阿里云业务空间的兼容地址和 `deepseek-v4.1-flash-1017`，需要该空间有权调用模型的密钥。不是把密钥填进网页，也不需要修改代码。

## 在 Render 填写

打开服务的 **Environment → Edit → Add Environment Variable**：

| KEY            | VALUE                                                                         |
| -------------- | ----------------------------------------------------------------------------- |
| `LLM_API_KEY`  | 自己的阿里云密钥                                                              |
| `LLM_BASE_URL` | `https://ws-wx3zg6zl1sf52rk4.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` |
| `LLM_MODEL`    | `deepseek-v4.1-flash-1017`                                                    |

点击保存并重新部署。后两项也可不填，代码会使用表中的默认值。已有的 `DEMO_PASSWORD` 等变量保留。不要把密钥写进仓库文件、截图或问题日志。

本机运行时，复制 `.env.example` 为 `.env`，只需补上 `LLM_API_KEY`。`.env` 已被 Git 忽略。更换其他业务空间时同时修改地址与密钥；更换模型时使用该空间支持的准确模型 ID。

## 登录后试这几句

1. “帮我给那款降噪耳机再进五十个，先出确认单”。检查待确认单是 `SKU-1001 / 50件`；库存仍为18件，确认后才变68件。
2. “给它写一段德国市场的推广文案”。沿用耳机，切换德国，生成中文、英文、德文草稿，点击来源可看原始素材。
3. “结合评论告诉我它有哪些缺点，退货要满足什么条件”。查看真实检索到的评论和退货政策编号。
4. “把德国那张已付款订单安排配送，先给我确认”。通过订单工具筛选唯一候选，生成配送确认单，不直接发货。
5. “背包库存补到一百件”。初始背包库存86件，应生成新增14件的草案；未说明数量时不会默认补20件。

回复下方显示本轮模型名称、成功返回的调用数、服务商报告的 Token 数。先收到逐字回复，最后显示完整答复、资料和待确认单。刷新页面后在作业记录里展开历史。

## 出现提示时

- **已配置，等待任务验证**：识别到了密钥，还没成功完成实际调用。提交一个任务后再看状态。
- **模型密钥或业务空间权限不正确**：检查密钥是否属于地址对应的业务空间，以及是否有该模型权限。
- **模型请求较多 / 响应超时**：稍后重试。程序会保留工具查询事实，并明确标注降级，不把规则结果冒充模型回答。
- **回复格式未通过检查**：模型生成的结构或引用不符合要求，这部分结果会退回查询事实。

模型每轮通常调用3次，多个助手协作时最多6次，可能产生模型费用。Token 统计只展示服务商实际返回的数值；中断或报错请求不保证有完整用量，不能作为账单。密钥错误不自动重试；临时错误仅有限重试，工作流默认总时限240秒。

商品、订单、供应商、物流、评论和政策仍是演示数据。模型接入不代表已接入真实店铺，也不代表真实采购、支付、退税或配送已完成。
