# 五分钟演示与面试讲解

## 1. 先说明问题

跨境运营需要同时看商品、库存、订单、营销和物流。内部团队要共享上下文，但供应商和物流不能直接读取内部整份会话状态。因此内部用 LangGraph 管状态，外部用 A2A 交换明确任务，MCP 负责业务工具调用。

先明确：业务数据是合成数据；配置密钥后由 DeepSeek 理解任务、分析工具结果和生成回复，没有密钥时回退规则演示。页面显示本轮实际模式与用量。真实协议调用与模拟业务数据是两回事。

## 2. 演示补货

输入“查询 SKU-1001 的库存，并补货50件”。观察路由 → 商品助手 → 供应商 A2A Task → MCP 库存查询 → 汇总。初始本地库存18件、供应商240件。生成确认单时不改变库存；确认后本地变68件、供应商190件。重复确认同一张单不会再增加50件。

讲解时打开 `workflow.py`、`external.py` 和 `store.py`：分别解释内部共享状态、外部任务边界和数据库事务。

## 3. 演示配送和跨助手共享

输入“查看 CB-2026002 订单，并生成德国市场营销文案和退货政策”。订单助手先读取商品 SKU-1002、目的地 DE，其他助手共享这份状态。供应商和物流只接收到完成任务需要的字段。

再输入“CB-2026002 安排配送”，确认后出现模拟运单，本地背包库存从86变85。已发货订单不能重复创建配送。

## 4. 演示记忆与来源

新建会话，输入“为 SKU-1002 生成德国市场营销文案”，再输入“再写一份营销文案”。第二轮沿用商品与市场，但不会沿用补货数量或自动执行旧操作。客服结果包含 `policy-return` 等来源编号。

## 5. 说明真实取舍

| 面试追问                     | 当前实现与边界                                                                   |
| ---------------------------- | -------------------------------------------------------------------------------- |
| 为什么不用一个巨大的 Agent？ | 用清楚的节点职责、共享状态和可观察的流程控制复杂度；模型可选                     |
| A2A 和 MCP 有什么区别？      | A2A 对外委派任务并返回 Task/Artifact；MCP 发现和调用具体工具                     |
| 内部助手并行吗？             | 当前顺序调度，订单先补全上下文；没有宣称并行执行                                 |
| Redis 和 Milvus 真用了吗？   | 有可切换适配器；默认演示分别用 SQLite 和本地哈希检索，页面 health 可核对         |
| 能保证不会超卖吗？           | 本地配送确认在同一事务内检查并扣库存；不是跨真实平台的分布式库存保证             |
| 断开后能继续任务吗？         | 当前没有 checkpoint 恢复；实体记忆持久化，但断线时需核对确认单再重试             |
| 真实上线还缺什么？           | 独立用户与角色权限、服务认证、平台 API、任务队列、重试补偿、分布式锁、审计与监控 |

不要把未接入的真实平台、语义模型、持久化 A2A Task Store 或完整 A2A 1.0 说成已完成。
